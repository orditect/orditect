# Orditect Wire Format (v0.1, ratifying)

**Status of this document**: normative for the serialized form of the
orditect-protocol data models. Where a model docstring and this document
disagree, this document wins; the docstring must be fixed.

## 1. Scope

Governs the **serialized form** of the five contract domains' models —
what any producer must emit and any consumer may rely on, independent of
transport or storage.

Explicitly out of scope:

- **Core hot records** (orditect-core Redis task records): internal
  mechanism data, not a published wire format. (Hot-record timestamps are
  mechanism-internal; orditect-core normalizes them separately.)
- **Lua ARGV / Redis key layouts**: implementation freedom of the hot path.
- **Transport**: files, message queues, RPC payloads, trace bundles are
  all legal carriers.

## 2. Serialization rules

Each rule is pinned by a test or enforced by the schema artifacts:

1. **Omit on None** — None-valued fields are omitted, never serialized as
   explicit nulls. Consumers read with `.get()`.
2. **Timezone-aware UTC datetimes** (T7) — offset mandatory; "Z" SHOULD be
   used, "+HH:MM"/"-HH:MM" equally valid. Enforced by an artifact pattern.
3. **Enums as lowercase strings** — members serialize to their values
   (SortDirection -> "asc"/"desc").
4. **UTF-8, unescaped non-ASCII** (`ensure_ascii=False` semantics).
5. **Field order not guaranteed** — exporters emit sorted keys for
   diff-friendliness; consumers must not rely on order.
6. **Compact separators** — no insignificant whitespace in canonical output.
7. **Finite floats only** — inf/nan serialize as null (discouraged).

## 3. Stability levels

| Level | Meaning | Applies to (v0.1.2) |
|---|---|---|
| **frozen** | change requires minor/major bump + CHANGELOG | model field semantics (names, types, optionality) |
| **ratifying** | being ratified; may be corrected by second-backend feedback before 1.0 | serialization details; all v0.1 artifacts |
| **experimental** | may change without notice | op envelope vocabulary; URN convention; `edge_write` op |

## 4. Artifacts

Versioned JSON Schema artifacts in `schemas/` are the publishable form of
this document. Generated by `scripts/generate_schemas.py` (single source
of truth), protected by the drift gate (`tests/golden/test_schema_drift.py`).
Never hand-edit.

| Artifact | Model(s) |
|---|---|
| `schemas/snapshot/0.1.json` | TaskSnapshot |
| `schemas/audit/0.1.json` | AuditEvent |
| `schemas/pointer/0.1.json` | TaskPointer |
| `schemas/query/0.1.json` | Page / Sort / SortDirection / TimeRange ($defs) |
| `schemas/dependency/0.1.json` | DependencyEdge / DependencyGraph ($defs) |

Artifacts live at the repository root under `packages/protocol/schemas/`
and are the normative reference for producers in any language; they are
deliberately distributed with the repository (and future spec site), not
inside the wheel — you reference them for validation, you do not import
them.

## 5. Entities and references

The addressable unit of the cold-data world is the **generation**, not the
task: `(task_id, step, execution_id)`. `task_id` and `execution_id` are not
two identifier systems — they form one hierarchical key ("node ×
generation"); a "task" is the aggregate projection of its generation rows.

Cross-domain references (all via natural keys, no new ID system):

- `TaskSnapshot.input_pointer` / `output_pointer` -> content blob (T5)
- `AuditEvent.task_id` -> task node of the snapshot domain
- dependency edge `child_id` / `parent_id` -> task nodes at both ends
- stream manifest placeholder `task_ref` -> flow task (deterministic-ID
  convention below)

Deterministic-ID conventions (business must not occupy reserved prefixes):

| Convention | Producer | Meaning |
|---|---|---|
| `exec-{uuid4hex[:12]}` | orditect-core | execution_id generation format |
| `enrich-{placeholder_id}` | orditect-stream | enrich task_id, zero-channel alignment |
| `budget:{root_task_id}` | orditect-flow | budget-ledger scope composition |

**URN convention (experimental).**
`urn:orditect:<domain>:<natural-key-parts>` is a typed reference string for
external systems (tickets, approval panels). URN semantics: identity and
self-description, never resolution. There is no global `resolve()`; models
carry no `uri` field.

## 6. Mechanism-field whitelists

Query-interface mechanism fields are closed sets (contract data in
`orditect.protocol.mechanism`). Out-of-whitelist inputs MUST be rejected
with `InvalidQueryError` — never silently fall back.

| Domain | sort.field | time_range applies to | group_by |
|---|---|---|---|
| audit | `created_at`, `event_id` | `created_at` | (n/a) |
| snapshot | `created_at`, `updated_at`, `expire_at` | `created_at` | `status`, `model` |

Business fields (payload / cost / error / business content) are never
whitelisted: the mechanism/business boundary is the business-isolation
boundary itself.

## 7. Operation semantics (op envelope)

A raw model row cannot distinguish `save` from `save_terminal` — T3's
terminal semantics would be unrecoverable from data alone. The op envelope
carries the operation at the log layer:

```json
{"v": 1, "op": "save_terminal", "ts": "2026-08-28T10:00:05Z", "data": { ...model payload... }}
```
